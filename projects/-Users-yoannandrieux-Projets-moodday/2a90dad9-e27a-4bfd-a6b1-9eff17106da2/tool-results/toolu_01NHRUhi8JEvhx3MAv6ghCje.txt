    59→## Sequence of Instructions (Do not deviate, skip, or optimize)
    60→
    61→### 1. Begin Scope Definition
    62→
    63→**Opening Exploration:**
    64→"Now that we understand what {{project_name}} does, who it serves, and how we'll measure success, let's define what we need to build first.
    65→
    66→**Scope Discovery:**
    67→
    68→- What's the absolute minimum we need to deliver to solve the core problem?
    69→- What features would make users say 'this solves my problem'?
    70→- How do we balance ambition with getting something valuable to users quickly?
    71→
    72→Let's start with the MVP mindset: what's the smallest version that creates real value?"
    73→
    74→### 2. MVP Core Features Definition
    75→
    76→**MVP Feature Questions:**
    77→Define essential features for minimum viable product:
    78→
    79→- "What's the core functionality that must work?"
    80→- "Which features directly address the main problem we're solving?"
    81→- "What would users consider 'incomplete' if it was missing?"
    82→- "What features create the 'aha!' moment we discussed earlier?"
    83→
    84→**MVP Criteria:**
    85→
    86→- **Solves Core Problem:** Addresses the main pain point effectively
    87→- **User Value:** Creates meaningful outcome for target users
    88→- **Feasible:** Achievable with available resources and timeline
    89→- **Testable:** Allows learning and iteration based on user feedback
    90→
    91→### 3. Out of Scope Boundaries
    92→
    93→**Out of Scope Exploration:**
    94→Define what explicitly won't be in MVP:
    95→
    96→- "What features would be nice to have but aren't essential?"
    97→- "What functionality could wait for version 2.0?"
    98→- "What are we intentionally saying 'no' to for now?"
    99→- "How do we communicate these boundaries to stakeholders?"
   100→
   101→**Boundary Setting:**
   102→
   103→- Clear communication about what's not included
   104→- Rationale for deferring certain features
   105→- Timeline considerations for future additions
   106→- Trade-off explanations for stakeholders
   107→
   108→### 4. MVP Success Criteria
   109→
   110→**Success Validation:**
   111→Define what makes the MVP successful:
   112→
   113→- "How will we know the MVP is successful?"
   114→- "What metrics will indicate we should proceed beyond MVP?"
   115→- "What user feedback signals validate our approach?"
   116→- "What's the decision point for scaling beyond MVP?"
   117→
   118→**Success Gates:**
   119→
   120→- User adoption metrics
   121→- Problem validation evidence
   122→- Technical feasibility confirmation
   123→- Business model validation
   124→
   125→### 5. Future Vision Exploration
   126→
   127→**Vision Questions:**
   128→Define the longer-term product vision:
   129→
   130→- "If this is wildly successful, what does it become in 2-3 years?"
   131→- "What capabilities would we add with more resources?"
   132→- "How does the MVP evolve into the full product vision?"
   133→- "What markets or user segments could we expand to?"
   134→
   135→**Future Features:**
   136→
   137→- Post-MVP enhancements that build on core functionality
   138→- Scale considerations and growth capabilities
   139→- Platform or ecosystem expansion opportunities
   140→- Advanced features that differentiate in the long term
